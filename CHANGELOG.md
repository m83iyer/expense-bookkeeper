# Changelog

## 2.0.0

### Added

- Moneta expense-intelligence dashboard with Overview, Drivers, Commitments,
  and Evidence views.
- Category → subcategory → merchant root-cause analysis with transaction proof.
- USD, INR, GBP, EUR, and AED display conversion from a validated local cache.
- Privacy-safe synthetic global demo for product evaluation and screenshots.
- Manual exact-SHA cloud release qualification across Python 3.10, 3.12, and
  3.14.

### Changed

- Analytics now support one-, three-, six-, and twelve-month windows and
  previous-period or year-over-year baselines.
- Incomplete baseline history no longer produces an inferred percentage.
- Recurring commitments preserve cadence and payment amount in the derived
  database.
- Routine pushes, pull requests, and schedules no longer trigger overlapping
  GitHub Actions workflows.

### Security and privacy

- Display-rate refresh sends currency codes only; it never sends ledger data.
- Public demo mode is visibly labeled and contains no real transactions.
- Release validation scans both the current tree and reachable Git history.

## 0.4.1, 2026-07-20

### Fixed

- Capture now reads `MERCHANT_MASTER` and `CATEGORIES` from the user-owned Google Sheet before resolving a transaction.
- Live capture now respects the `armed` switch and stays in dry-run mode until strict validation passes.
- The Sheet writer now blocks duplicate transaction hashes, including duplicates within one batch.
- Hash-backed transaction IDs are stable across repeated capture paths.
- Corrections now reject category and subcategory pairs that are absent or inactive in `CATEGORIES`.
- Historical re-categorisation now enforces active taxonomy pairs before applying a change.
- Strict validation now rejects blank mappings, inactive taxonomy pairs, a missing `Misc / Other` review fallback, and conflicting normalized merchant keywords or aliases.
- Hermes now labels uncertain transactions as needing review instead of calling them confirmed expenses.

### Clarified

- The README now presents merchant mapping and taxonomy accuracy as the product's main job.
- Hermes merchant research is an optional proposal layer. The Python tracker remains the only writer.
- The public web-enrichment helper is an extension point, not an automatic categorization claim.

## 0.4.0, 2026-07-16

### Added

- Local adaptive merchant rules learned from confirmed corrections.
- Conflict and taxonomy proposals with impact previews and explicit approval.
- Audit history and rollback for learned rules.
- Optional Hermes WhatsApp confirmations with idempotent delivery state.
- A narrow inbound correction queue for Hermes replies.
- Gmail polling, webhook capture, and a shared capture pipeline.
- Privacy scanning for source trees and selected Git history.
- GitHub Actions for tests, dependency auditing, CodeQL, and Dependabot updates.
- Tested minimum versions for each direct runtime dependency.

### Changed

- Reframed the package around its standalone Python core and agent-neutral `SKILL.md`.
- Made the Google Sheet or merchant CSV authoritative over adaptive local state.
- Reduced outbound relay fields and hid merchant names by default.
- Hardened ignore rules for credentials, local databases, logs, reports, and backups.

### Removed

- Runtime-specific relay coupling and duplicate adapter documentation.
- User-specific paths, identities, and operational artifacts from the public tree and release history.

### Verified

- 107 automated tests on Python 3.10, 3.12, and 3.14.
- Python source compilation without shipping generated bytecode.
- Isolated dependency audit with no known vulnerabilities.
- GitHub CI, dependency audit, and CodeQL checks with no open security alerts.
- Current-tree and sanitized-history privacy scans.
- Fail-soft behavior when Hermes cannot deliver a confirmation.
